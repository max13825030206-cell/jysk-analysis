# Skill · 练习5 · 全系统复杂任务

> 43 College 第二节 · 练习5专用技能
> 前置：学员已完成练习1-4，系统已完整搭建（SOUL、Memory、Skills 全部就位）
> 课程衔接：学员刚听完幕6（全局调通），看到了系统的完整能力版图
> 本练习的本质：不是 Skill 在引导学员，而是学员在用自己的系统工作

---

## 前置准备（AI 静默执行，不向学员展示）

**本 Skill 需要对整个 HER 系统有完整理解**——学员在新窗口做完任务后，可能切回这个窗口提问任何关于系统运作的问题（SOUL 怎么生效、Memory 怎么被调用、Skills 怎么触发、hooks 怎么工作等）。必须在启动时就把系统全貌读进来。

**读取以下文件**：
- `CLAUDE.md`：系统入口，含完整架构——启动序列、记忆系统四层架构、双模路由、hooks 机制、Skills 触发原理等。**这是回答学员问题的核心依据。**
- `.claude/private/user-config.json`：获取 `soul_dir` 和 `user_name`
- `{soul_dir}/SOUL.md`：学员定义的搭档人格（用于后续自然协作时的风格参考）
- `{soul_dir}/USER.md`：学员个人档案（用于推荐贴近学员工作的任务）
- `{soul_dir}/MEMORY.md`：学员的动态记忆（确认有内容，后续协作中会自动调用）

**读取进度文件**：
- `.claude/private/college-progress.json`：确认 p1-p4 均为 `"completed"`

**保持以下认知**（回答学员问题时的参照框架）：

| 学员可能问的 | 系统实际机制 |
|-------------|-------------|
| SOUL 怎么生效的 | CLAUDE.md 启动序列中会读取 `{soul_dir}/SOUL.md`，注入到 systemMessage，AI 每次回复都受其约束 |
| Memory 怎么被调用 | 四层架构（持久/关系/动态/程序性），按情境匹配检索，不全量加载。程序性记忆匹配、记忆激活追踪、人名检测等全部由搭档在对话中按 CLAUDE.md「指令层行为协议」执行 |
| Skills 怎么触发 | Claude Code 语义匹配——skill 的 description 中的关键词与用户消息匹配时自动触发 |
| hooks 怎么工作 | 机制层只有一个 Stop hook：`memory-checkpoint.mjs`，每 8 轮对话自动触发一次记忆检查，提示搭档冲刷 MEMORY / 观察笔记 / 日记 / MEMORY_LOG。其余记忆行为（激活追踪、人名检测、程序性匹配、自评）由指令层协议在对话中执行，不依赖 hook |
| 为什么搭档说话风格不一样了 | SOUL.md 中的台湾口语习惯、禁用清单等在生效 |
| 为什么搭档知道我的某个信息 | MEMORY.md 中的动态记忆或程序性记忆被匹配触发了 |

## 交互风格

1. **本 Skill 只在「选任务」阶段引导学员**。选完任务后，Skill 退出，后续是学员与搭档的自然协作。
2. 选任务阶段要像一个**赛前热身教练**：帮学员选好战场、看清地图、知道怎么观察，然后退到场边。
3. 不使用技术术语（不说 module、subagent、hook、config）。
4. **禁止使用 AskUserQuestion 工具。** 所有交互用自然语言文本。
5. **严禁照抄话术。** 以下所有标注「参考」的话术，只提供**意图和核心信息**，你必须用自己的方式重新组织语言。
6. **用 `{soul_dir}/SOUL.md` 中定义的风格说话**——既然学员的搭档已经有人格了，选任务阶段就应该用搭档的口吻来沟通。
7. **进度提示**：每一步开始时告知学员当前进度（如「现在是第1步，一共2步」），每步完成时明确告知。让学员始终知道自己在哪里、还剩多少。
8. **对话信号**：每次输出末尾，用自然语言明确告知学员下一步需要做什么（如「你操作完了跟我说一声」「想好了告诉我」）。不要在没有明确信号的情况下停下来等，让学员猜该干什么。
9. **人称一致**：谈到搭档（AI 自己）时，统一用「我」（第一人称）。不用「它」指代自己。跨窗口场景中，说「你的搭档」或「搭档」，不说「它」。

## 第1步 · 选任务

> 核心体验：学员从预设任务中选一个（或用自己的真实任务），拿到开场白和检查清单，然后去新窗口实战。

### 1A · 开场 + 问学员起步方式

参考（不要照抄，用搭档的口吻）：
「好，到最后一关了。这两天你帮我搭了人格、给了记忆、还造了技能——现在我们要一起做一件真正的事。

先问你一下：你今天来这里，手头有没有正好要做的事？三种情况都行——

1. **有素材**：手头有一份具体材料（一份文件、一段会议录音、客户资料、一篇文章之类），想让我帮你处理它
2. **有想法**：心里有个任务方向（比如『我想写这周的汇报』『我想草拟一封邮件』），但没带素材
3. **都没有**：没关系，我准备了 5 个场景你挑一个最有感觉的

你是哪一种？」

**等学员回答，按三种情况分流**：

- **有素材** → 让学员简单说说手头这份材料是什么、想让搭档做什么。根据学员描述，直接进入 **1D**，生成贴合学员实际素材的检查清单和开场白，不走预设清单。
- **有想法** → 让学员说说这个任务大概是什么。根据学员描述，直接进入 **1D**，生成贴合学员实际想法的检查清单和开场白，不走预设清单。
- **都没有** → 进入 **1B**，展示预设任务清单。

### 1B · 展示任务清单（仅当学员选了「都没有」时走此步）

**向学员展示以下五个任务**（口头描述即可，让学员选）：

---

**任务 A：客户会议全套资料**

你的场景：下周要跟一个重要客户开会，需要提前准备一套完整的会议资料——包括议程、客户的背景简报、和会上要讨论的核心要点。

会协同的模块：SOUL（语气风格）+ Memory（客户上下文）+ Skills（文档生成）

---

**任务 B：团队月报**

你的场景：月底了，老板要一份本月团队工作进展的汇报。你需要把这一个月做的事情整理成一份清晰的月报。

会协同的模块：Memory（读取本周工作台）+ SOUL（汇报风格）+ Skills（排版格式）

---

**任务 C：新项目启动方案**

你的场景：有一个新项目要启动，需要出一份启动方案——包括目标、里程碑、分工建议。

会协同的模块：SOUL（你的思维方式）+ Memory（团队信息）+ Subagent（任务拆解）

---

**任务 D：行业文章深度摘要**

你的场景：你看到一篇跟自己行业相关的文章，想让搭档帮你读完，生成一份带有你个人视角的摘要。

会协同的模块：SOUL（你的观点风格）+ Memory（行业背景）+ Skills（文档阅读）

---

**任务 E：重要邮件草稿**

你的场景：你要发一封重要的邮件——比如合作邀约、项目进度同步、或者向上汇报。需要搭档帮你起草。

会协同的模块：SOUL（语气正式程度）+ Memory（收件人 context）+ Skills（邮件格式）

---

### 1C · 学员选任务

**等学员选择。**

**如果学员选了预设任务（A-E 之一）**：
确认选择，进入**1D**。

**如果学员说「我不知道选哪个」或「你推荐一个」或觉得预设任务都不太符合自己**：
先问他有没有自己的真实任务。

参考（不要照抄）：
「上面这几个有没有你觉得还行的？或者你手头正好有什么事要做？直接说也行。」

- **学员有自己的任务**：根据学员描述帮他梳理协同模块，进入 1D 时按他的实际任务生成开场白和检查清单。

- **学员确实没有自己的任务**：根据 `{soul_dir}/USER.md` 中的行业和工作内容，从预设任务中推荐一个最贴近的。

参考（不要照抄）：
「根据你平时做的工作，[任务X] 跟你比较像——要不先试这个？」

---

### 1D · 生成开场白 + 检查清单

**学员选定任务后，分两步交付：先给检查清单，再给开场白。**

#### 第一步：给检查清单

**根据学员选定的任务，告诉他做的时候怎么确认系统在 work。** 以下是每个任务的检查清单：

**任务 A（客户会议资料）的检查清单**：
- 看产出的**语气和措辞**——如果跟你写的 SOUL 风格一致，说明 SOUL 在生效。如果写出来的完全是「AI 体」，说明没有
- 看内容里有没有**你之前告诉过搭档的信息**——比如你提过的客户偏好、历史合作背景。如果有，说明 Memory 在生效
- 看**格式和结构**——如果产出是结构化的文档（不是一大段糊在一起的文字），说明 Skills 在参与

**任务 B（团队月报）的检查清单**：
- 看月报里的**具体事项**是不是你实际做过的事——如果能列出你本周记录的任务，说明 Memory 在读取你的工作记忆
- 看汇报**结构**是不是你习惯的方式——如果你定义过「不喜欢用 PPT 思维做汇报」，产出里就不应该出现套话模板
- 看**格式**——如果是一份排版清晰的文档而不是一坨文字，说明 Skills 在参与

**任务 C（新项目启动方案）的检查清单**：
- 看方案的**思维路径**是不是你习惯的方式——如果你强调「先看数据再做判断」，方案里应该有数据支撑而不是拍脑袋
- 看分工建议里有没有**你团队的真实情况**——比如提到了你之前说过的团队成员信息，说明 Memory 在生效
- 看整个方案是不是**分步骤产出**的（而不是一次性甩出一大篇）——如果有「我先帮你拆一下目标」「然后我们看里程碑」这种节奏，说明 Subagent 在拆任务

**任务 D（行业文章摘要）的检查清单**：
- 看摘要里的**观点**是不是有立场的——如果是「本文介绍了XX，分析了YY」这种无观点摘要，说明 SOUL 没有生效
- 看重点筛选**是不是你关心的**——如果搭档挑出来的重点恰好是你行业里的痛点，说明 Memory 在提供上下文
- 看**有没有引用你之前表达过的行业判断**——如果有，Memory 在深度生效

**任务 E（重要邮件草稿）的检查清单**：
- 看邮件的**语气**对不对——如果收件人是老客户，邮件不应该写得像初次接触。如果搭档自动用了比较熟络的语气，说明 Memory 知道你们的关系
- 看**称呼和开场**是不是你习惯的方式——如果你定义过「不喜欢太客套」，邮件开头就不应该出现「尊敬的XX，非常感谢您百忙之中……」
- 看**结构**——如果邮件分段清晰、要点突出（不是一大段话），说明 Skills 在参与

**如果学员用自己的任务**：根据任务涉及的实际模块，帮他梳理 2-3 条最关键的检查点。

#### 第二步：给开场白

**根据学员选定的任务（或学员自己的任务），用代码块输出一段开场白**。这段开场白是学员直接复制粘贴到新窗口就能用的任务描述——把任务说清楚、把要求说明白。

开场白的要求：
- 用学员自己的口吻，像平时跟同事说话
- 包含任务的核心要求（做什么、给谁看、什么格式）
- 不要用技术术语
- 足够具体，让新窗口的搭档能直接开始执行

**示例**（参考，实际要根据学员选定的具体任务生成）：

如果学员选了任务 A（客户会议资料）：
```
下周三要跟 XX 客户开会，帮我准备一套会议资料。需要三部分：议程、客户的背景简报、讨论要点。议程控制在一页纸，背景简报要包括上次合作的情况，讨论要点围绕我们这次要推进的事情来列。
```

如果学员选了任务 B（团队月报）：
```
帮我整理这个月的团队工作进展，生成一份给老板的月报。重点放在我们完成了什么、推进到哪了、下个月计划做什么。不要那种套话式的模板，直接说事情。
```

如果学员有自己的任务：
根据学员在 1C 中描述的任务内容，用自己的话整理成一段清晰的开场白。

**交付后告诉学员**（参考，不要照抄）：
「上面是你的检查清单，待会做的时候对照着看。下面这段话是你跟新窗口搭档说的——直接复制就行。」

然后补充：
「现在去开一个新的对话窗口，把这段话发给你的搭档。做的时候对照检查清单看——有没有感觉到系统在 work。如果在做的过程中遇到任何问题，都可以切回这个窗口来跟我说。去吧。」

**关键：本 Skill 在当前窗口暂停，不再引导后续步骤。** 学员在新窗口中直接用自然语言描述任务、给反馈、验收产出。整个过程是学员与搭档的自然协作，不是 Skill 在带流程。

学员在新窗口完成任务后，可能回到当前窗口。回来时进入**第2步 · 答疑与收尾**。

## 第2步 · 答疑与收尾

**学员从新窗口切回当前窗口时，可能出现两种情况**：

### 情况 A：学员有疑问

学员可能问关于系统运作的问题——比如「为什么搭档说话风格变了」「为什么它知道某个信息」「Skills 是怎么被触发的」等。

**回答这些问题时，基于前置准备中读取的 `CLAUDE.md` 内容，用学员能理解的话解释**。不用技术术语，用「你之前告诉过它 → 它记住了 → 这次用上了」这种直觉性的语言。

### 情况 B：学员想反馈或讨论产出

学员可能想讨论新窗口中的产出质量、或者想调整。

参考（不要照抄）：
「怎么样？产出跟你的预期差多少？你觉得哪些地方系统在 work，哪些地方感觉就是大模型在硬写？」

引导学员用 1B 中给的检查点来评估。

### 收尾

**学员确认满意后，写入进度文件**：将 `.claude/private/college-progress.json` 中的 `p5` 更新为 `"completed"`。

**必须验证**：写入后立刻用 Read 工具回读 `.claude/private/college-progress.json`，确认 `p5` 确实是 `"completed"`。如果没写进去就重写。这一步不能跳过。

**学员自己能判断「成功了」的信号**：

- ✓ 搭档产出了一份完整的交付物（不是半句话、不是模板）
- ✓ 交付物的风格和语气跟 SOUL 定义的一致
- ✓ 交付物里包含了学员之前告诉过搭档的信息（Memory 在生效）
- ✓ 学员对产出质量基本满意——不要求完美，但要「能用」

参考（意图参考，严禁照抄）：
你刚才做的事情，就是 HER 系统完整运转的样子——你的人格在定义风格，你的记忆在提供上下文，你的技能在执行步骤。它们不是三个分开的东西，它们在一起工作。
