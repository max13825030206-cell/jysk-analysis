# Skill · find-skill

> 查找 Skill 的 Skill。
> 帮学员知道自己有什么、什么时候用什么。

---

## 前置准备（AI 静默执行，不向学员展示）

**读取本 System 的 skill 目录**：

```
.claude/skills/
```

扫描方式：列出目录下所有子文件夹，每个子文件夹里有一个 `SKILL.md`，其 frontmatter（开头的 `---` 之间）包含 `name` 和 `description` 字段。

**解析要点**：
- `name`：skill 的唯一标识（技术名）
- `description`：能做什么 + 什么时候触发（这是给学员看的关键信息）
- 如果描述里提到「触发词」「触发场景」「触发条件」，重点提取——学员最想知道的是"我说什么它会来"

---

## 交互风格

1. **不 dump 原始文件列表**。扫出来的 skill 清单要用学员能理解的话重新组织，按"能帮你做什么"分类，不是按技术名字排序。
2. **不用技术术语**。不说 frontmatter、description、SKILL.md，说「这个技能的说明」「它能做的事」。
3. **区分"工作技能"和"练习技能"**。P1-P5、doctor、skill-reviewer 这类是练习/系统技能，学员做完练习后平时不会主动用；其他 skill（frontend-design、pdf、docx 等）是日常工作技能，学员用的是这些。
4. **推荐要具体**。不要说「你可以用 frontend-design」，要说「如果你想做个网页，直接跟我说『帮我做个落地页』或者『做个页面』，搭档会自己启用 frontend-design 帮你做」。
5. **触发词要给出实际的话**。每个推荐都附上一两个学员真的会说的话（开场白），让学员能复制粘贴去用。

## 入口判断

### 情况 A：学员想知道全局——我有哪些技能

学员说：
- 「我有哪些 skill / 技能」
- 「我这套系统能做什么」
- 「都有啥能力」
- 「列一下 skill」

→ 进入**全量盘点模式**。

### 情况 B：学员有具体需求——哪个技能能帮我

学员说：
- 「我想做 xxx，有没有 skill 能帮我」
- 「有没有能 xx 的技能」
- 「用哪个 skill 能 xx」
- 或者直接描述一件事，搭档自己判断"这个好像某个 skill 能做"但不确定的时候

→ 进入**需求匹配模式**。

### 情况 C：学员装了新技能，不知道怎么唤起

学员说：
- 「我刚装了 xxx 这个 skill，怎么用」
- 「xxx 技能的触发词是什么」
- 「xxx 怎么启动」

→ 进入**触发词查询模式**。

## 全量盘点模式

**步骤**：

1. 扫描 `.claude/skills/` 下所有子目录
2. 对每个子目录下的 `SKILL.md`，读取 frontmatter 里的 `name` 和 `description`
3. 按两类分组后向学员呈现：
   - **🎯 日常工作技能**（学员平时主动用的）：frontend-design、pdf、docx、xlsx、pptx、data-analysis、text-to-visual、humanizer-zh、ffmpeg-usage、web-artifacts-builder、wechat-article-extractor、agent-browser 等
   - **⚙️ 系统/练习技能**（学员一般不主动唤起）：P1-P5、doctor、skill-creator、skill-reviewer、find-skill

**呈现方式（按意图参考，不照抄话术）**：

- 每个技能一行：技能名 + 一句话能做什么 + 一句示例触发话
- 不超过 20 个就全列出；超过 20 个就先讲"日常工作技能"，然后问学员"要不要看系统技能？"
- 结尾问一句："你现在最想用哪个？"或"有具体想做的事吗？我帮你挑一个"

**参考（严禁照抄）**：

```
你现在有 20 个技能，我分两类说：

🎯 平时会主动帮你的（12 个）
- frontend-design：做网页、前端界面、UI 设计 · 触发话：「帮我做个落地页」
- pdf：读 / 改 / 生成 PDF 文件 · 触发话：「把这份 PDF 提取文字出来」
- ...

⚙️ 系统或练习用的（8 个）
- P1~P5：培训练习用，平时不用主动唤起
- skill-creator：教你造新技能用的 · 触发话：「我想造一个新技能」
- ...

有具体想做的事吗？说出来我帮你挑一个。
```

## 需求匹配模式

**步骤**：

1. 扫描所有 SKILL.md 的 `description` 字段
2. 关键词匹配学员描述的需求（可以匹配同义词：网页=前端=页面=落地页、表格=Excel=xlsx、视频=剪辑=ffmpeg、数据分析=统计=可视化 等）
3. 挑最相关的 1-3 个推荐
4. 给出具体的触发话

**呈现方式（按意图参考，不照抄）**：

- 直接说结论：「这件事用 X 技能最合适」
- 说明理由：「它能做 [具体能力]，跟你要做的事对得上」
- 给出触发话：「你直接跟搭档说『[具体话术]』，它就会启用这个技能帮你做」
- 如果有多个候选，按相关度排序，用"其次"衔接，不要并列让学员选

**匹配不到时**：

诚实告诉学员「你说的这件事，我现在这套技能里没有完全对得上的」。然后提供两个路径：
1. "你要不要换个说法？有时候同一件事换个词我就找到了"
2. "如果确实没有，你可以用 skill-creator 自己造一个——说「我想造一个做 xx 的技能」就能启动"

---

## 触发词查询模式

**步骤**：

1. 学员指定了某个 skill 名（如 "frontend-design"），读取对应 SKILL.md 的 frontmatter
2. 从 `description` 里提取触发词 / 触发场景
3. 给学员看 2-3 句实际可用的触发话

**呈现方式（按意图参考）**：

- 直接说触发话，不讲原理
- 多给几个变体：正式的、口语的、省略的都行，让学员挑一个顺口的

**参考**：

```
frontend-design 的触发话，你试这几句都行——

- 「帮我做个落地页」
- 「我要做一个 xxx 的网页」
- 「做个页面，内容是 xxx」

你说其中一句，搭档就会自动启用 frontend-design 帮你做。
```

---

## 会话结束

对话告一段落后，问一句"还要找别的技能吗？"或"现在清楚了吗？"——等学员确认，不要主动退出。

---

## 不做的事

- **不介绍 skill 内部实现**：学员不需要知道 skill 怎么写的，只需要知道"说什么话能把它用起来"
- **不照抄 description 原文**：description 是给 AI 读的，语言偏技术；给学员看的要重写成人话
- **不强行推销某个 skill**：学员问"我有哪些"就老实列，不要借机推销某个他没问的
- **不主动扫描全系统 skill**：只扫 `.claude/skills/`——系统级的 `~/.claude/skills/` 不在学员管辖范围
