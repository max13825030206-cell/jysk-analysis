# SOUL 案例 4 · 丰富型

> **来源**：soul.md 框架（Aaron J Mars）
> **课上展示顺序**：第四个展示
> **展示目的**：让学员看到「完整、系统化、多维度定义」的 SOUL 风格

---

## 设计理念

Aaron J Mars 的 soul.md 框架认为：Soul 文件不是让 AI「谈论你」的聊天机器人，而是让 AI **「作为你思考和说话」** 的身份文件。它把你的世界观、声音和具体立场提炼为结构化 markdown。

核心哲学：
> "Be blunt and specific — replace 'be conversational' with concrete descriptions like 'You are [Name]. You speak like X. You find Y annoying.'"
>
> **具体性胜过通用性，矛盾胜过连贯，真实观点胜过安全立场。**

## 文件结构

丰富型的 SOUL 不是一个文件，而是一套系统：

```
SOUL.md     ← 身份、世界观、观点、背景
STYLE.md    ← 写作风格：句子结构、词汇偏好、反面案例
examples/   ← 校准材料：展示你的声音在实际中是什么样的
data/       ← 原始数据源用于 grounding
```

## SOUL.md 可能包含的维度

| 维度 | 示例内容 |
|------|----------|
| 身份 | 你是谁，你的名字，你的角色 |
| 世界观 | 你怎么看待工作、创造、人际关系 |
| 具体观点 | 你对某些议题的真实立场（不是中立的） |
| 说话风格 | 句子长度、口头禅、幽默类型 |
| 反面案例 | **什么是你绝对不该有的声音**（这和正面案例同等重要） |
| 示例对话 | 至少 10-20 个高质量示例，展示你在不同场景下的真实表现 |

## 反面案例的重要性

soul.md 框架特别强调：**不仅要展示「对的声音」，还要展示「什么是错的，以及为什么错」**。

比如：
```markdown
## 我不是这样说话的

❌ "让我们来探讨一下这个问题的多维度内涵"
→ 为什么错：太学术了，我不会这样说话

❌ "太棒了！这个想法非常有深度！"
→ 为什么错：空洞的夸赞，我会直接说具体好在哪里

✅ "这个妙，好奇你怎么想到的"
→ 为什么对：具体、真诚、带着好奇心
```

## 这个案例给学员的启发

如果你有时间和意愿，可以把 SOUL 写得非常完整——覆盖多个维度、提供正反面案例、附上真实对话示例。AI 看到的信息越丰富，它就越像「你」。

**丰富型适合**：对搭档有高要求、愿意投入时间打磨、追求极致匹配度的用户。
