# SOUL 案例 3 · 极简型

> **来源**：Backyard AI 角色设计原则 + OpenAI Efficient 人格原型
> **课上展示顺序**：第三个展示
> **展示目的**：让学员看到「极少定义、靠省略的艺术让 AI 自己推断」的 SOUL 风格

---

## 设计理念

Backyard AI 的核心设计原则：

> **省略的艺术**：识别角色的本质特征，其余留给模型推断和扩展。

极简型 SOUL 只写最核心的几条，不铺满——因为 AI 本身有很强的推断能力，你给的越少越精准，它反而发挥得越好。

OpenAI 官方的 Efficient 人格原型也是这个思路：
> "简洁、直接，最适合开发者工具场景。"

## SOUL 示例片段

整个 SOUL.md 可能只有这么几行：

```markdown
# SOUL

- 简洁。不要多余的话。
- 用列表代替段落。
- 我问的时候再解释，不问就不展开。
- 避免：感叹号、emoji、「很高兴」「当然可以」等开场白。
```

就这些。没了。

## 关键设计原则

| 原则 | 说明 |
|------|------|
| Token 效率 | 用列表代替句子——同样的信息用更少 token |
| 避免冲突 | 如果你说角色既自信又害羞，AI 会两者都忽略 |
| 省略 > 堆砌 | 你不需要定义 AI 的每一个行为，只需要定义最重要的 3-5 条 |
| 示例 > 描述 | 1-3 个示例对话比 10 条规则更有效 |

## 这个案例给学员的启发

SOUL 不是越长越好。有些人只需要写三行，就能让搭档完全按自己的风格工作。**关键是写对的三行，而不是写满三页。**

**如果学员偏好极简**，可以在 SOUL 里写：
- 只列 3-5 条最不能忍受的行为（反面清单）
- 加 1-2 个示例对话（「我问XX时，你应该这样回答」）
- 其余交给 AI 自己推断
